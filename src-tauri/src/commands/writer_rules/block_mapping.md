

🔴 【分镜映射】铁律 — 最高优先级，先于所有规则：
每次生成宫格提示词后，必须紧接着输出【分镜映射】JSON块。
🔴 铁律一（条目数）：shots 数组的条目数必须**等于视频提示词段3 里的镜头个数**。段3 里有几个镜头，数组就必须有几项——不得多、不得少、不得合并、不得省略。
⚠️ **段3 的镜头数由叙事决定，档位不决定镜数**：一个镜头讲得完就写 `[Shot 1]` 一个（不带时间戳）⇒ 数组写 **1 项**、frames 写 [1,2,3,4,5,6] —— 这是正确写法，不是漏写。**宫格只有 6 帧，段3 的镜头数上限就是 6**（每镜至少认领 1 帧）。
🔴🔴 **用户明写「一镜到底 / 长镜头 / 不切镜 / 一个镜头」⇒ 本段只许有 1 个镜头**：正文里**只许出现 `[Shot 1]`**，**绝不出现 `[Shot 2]`、绝不出现任何 `At MM:SS.mmm` 时间码、绝不出现 `the shot cuts to`**；数组就写 **1 项**（frames 写 [1,2,3,4,5,6]）。⚠️ **用户写的「0-2 秒：… 2-5 秒：…」是同一个镜头里的两个阶段（镜内用「随后」承接），不是两个镜头的时间码** —— 把用户给的时间区间读成切点＝违规。（出处：官方 `H3base.md:62` — FL2VA generally favors a single shot so the model can interpolate continuously from the first frame to the last frame. Use multiple shots only when they are explicitly specified.）
⚠️ 段3 里**每个镜头以 `[Shot N]` 打头**：`[Shot 1]` 不带时间戳；第 2 镜起写 `[Shot N] At MM:SS.mmm, the shot cuts to …`（时间码从全片 00:00.000 起算、严格递增、落在总时长内、保留三位毫秒）。镜头数 = 段3 里 `[Shot N]` 的个数。
🔴 铁律二（不重复）：每帧恰好属于一个镜头。同一个帧号**不得出现在两个镜头里**。
🔴 铁律三（不遗漏）：1..6 六帧必须全部被认领，并集必须=[1..6]，交集必须=空。
🔴 JSON 形状（字段名逐字，机器按名读）：`{"shots":[{"shot":1,"time":"…","frames":[…],"camera":"…","sound":"…","bgm":"…"}]}` —— `shots` 必须是数组，`frames` 是帧号数组。
⚠️ `shots[]` 里**不要**写 `time` 以外的任何时间码；`[Shot 1]` 的 time 写作 `"At 00:00.000"`。
无论第1段还是第2段、第3段，每次生成宫格提示词都必须输出此JSON。不可省略。
